# What the evidence currently shows

Nuluno is not claimed to be universally faster, cheaper, or the first system with persistent agents. The public receipts distinguish executable behavior, model-authored method proposals, and commercial outcomes.

| Question | Evidence | Limit |
|---|---|---|
| Can a new user install the core? | Anonymous public clone, new environment, installed S01 starter, live public GET | Tested host combinations are recorded, not all operating systems |
| Does task identity survive a retry/restart? | Same saved run, task and receipt; actual process/container replacement | Requires a running host and retained state |
| Can new methods be rejected? | Two independently evaluated source suites rejected V1/V2 | Rejection is not successful sales improvement |
| Does the Engine beat a bare agent? | One earlier matched Notavue public-research pair: both 7/7 facts; bare 45.246 s, Engine 54.750 s | N=1 per arm; older commercial research API, not this community-version performance benchmark |
| Is it cheaper? | Model, host, source, platform and human bills are incomplete | Full cost unknown; no cost advantage claimed |
| Does it increase sales across products? | No held-out sales A/B acceptance yet | Not demonstrated |

## Independent evaluation protocol

Freeze the candidate before revealing new products. Register all products and success criteria, including failures and unavailable sources. Give both arms the same model configuration, initial tools, account permissions, budgets, time window and attribution rules. Keep the baseline competent: it may use persistence and retry primitives already available to it. Record model calls, token accounting, actual invoices, provider charges, hosting, human handoffs, refunds and delivery reserves. Unknown values remain null.

For every run keep the source/body hashes, original receipt/task identities, external native result and independent outcome assessment. Reject a candidate if required facts regress, if costs exceed limits, if evidence is missing or if authority expands. Retain the original method for rollback. Declare a commercial improvement only after adequate matched real tasks and a new-product holdout, not a source-formatting demo.

## Related work, without unsupported superiority claims

[LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) provides checkpoint and store mechanisms for agent state. [Composio](https://docs.composio.dev/docs) provides tool integration and managed authentication, including token isolation. [GEPA](https://github.com/gepa-ai/gepa) optimizes prompts, code and other artifacts through evaluation. These are overlapping capabilities, not proof that Nuluno is unique or outperforms them.

Nuluno's concrete integration target is sales workflows with explicit goal evidence, original task/receipt reuse, scoped account authority and versioned method checks. Its narrower public starter and current failures are documented so the combination can be assessed and improved. Related documentation was checked on 2026-11-14; this table is a capability map, not a head-to-head benchmark.
